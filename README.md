# RuPay Benefits

A private, mobile-friendly workspace for managing bank/card variants, cardholders, benefits, usage cycles and voucher inventory.

## Features

### Card variant management
- Create reusable card variants with issuer, network, annual fee and notes.
- Define multiple benefits per variant, each with a category, reset cycle, usage cap, unit and conditions.
- Edit and maintain variant definitions. A variant cannot be deleted while cards are assigned to it.


### Benefits List
- Create a reusable master list of benefits, each with a name, category and description.
- Select benefits from the list when creating or editing a card variant; one benefit can be reused across many variants.
- Set the usage cycle, limit, unit and variant-specific conditions separately for each selected benefit.
- Existing variant benefit entries are migrated into the Benefits List automatically while preserving their usage IDs.

### Cards and cardholders
- Add multiple cards and assign each to a configured variant.
- Assign cards to yourself or a cardholder record.
- Store a nickname, issuer/network snapshot, last four digits only, expiry month, status and notes.
- Maintain cardholders with relationship and optional contact details.
- Benefit definitions are automatically available for each card assigned to that variant.

### Benefit tracker
- Track benefits independently for each card.
- Log usage by date, quantity, amount and notes.
- Show used and remaining allowance for monthly, quarterly, semi-annual, annual and one-time cycles.
- Enforce configured usage limits when recording a benefit use.
- Inspect usage history and undo an incorrect usage entry.

### Voucher and supplier management
- Add voucher codes individually or in bulk (one code per line).
- Track Generated by me, Cardholder cards and Purchased from others origins.
- Store cardholder/card association or supplier name and phone.
- Search/filter by brand, origin and status; track Available, Sold and Redeemed.
- Edit voucher details, copy codes, bulk-select codes and view supplier purchase history.
- View upcoming expiry dates.

### Backup and cloud storage
- JSON export/import includes variants, cards, cardholders, benefit usage and vouchers.
- Firebase Authentication uses email/password.
- Cloud Firestore stores each account at `users/{uid}/workspace/main`.
- Firestore rules restrict each account to its own workspace.
- Legacy cards/vouchers are retained and earlier card benefit notes are migrated to editable legacy variants.

## Firebase setup and upgrade

Follow **[FIREBASE_SETUP.md](FIREBASE_SETUP.md)**. The Firebase web configuration is public client configuration; never commit service-account JSON files or private keys.

For this release, update Firestore Rules using the current contents of `firestore.rules` and publish them in Firebase Console before relying on cloud saves. The new app stores these arrays: `cards`, `vouchers`, `variants`, `holders`, and `benefitUsages`. Existing cards/vouchers remain in the same document.

## Important security and storage notes

- Never store full card numbers, CVVs, PINs, OTPs, banking passwords or payment credentials.
- The app stores only the last four digits for card identification.
- Firestore's single-document size limit and usage quotas still apply. This version uses one workspace document per account; export backups regularly. A future scale-up can move records into per-record subcollections.
- Set a Google Cloud budget alert and monitor Firebase usage. Free allowances are not unlimited.
- No Oracle VM, Docker, Node server or PostgreSQL deployment is required for the static web app.
