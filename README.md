# RuPay Benefits

A personal workspace for managing credit-card benefits and voucher inventory.

## Included in this first version

- Add credit cards with issuer, network, last four digits, benefit cycle, and benefit notes.
- Add voucher codes one at a time or in bulk (one code per line).
- Keep one brand-wise inventory across every origin: **Generated by me**, **Family cards**, and **Purchased from others**.
- Filter vouchers by brand, origin, status, and search text.
- Open any voucher to inspect its code, source, expiry, value, and provenance.
- For purchased vouchers, save the seller's name and phone number against every code in the batch.
- Track **Available**, **Sold**, and **Redeemed** separately.
- View supplier purchase history and upcoming expiries.
- Export and restore a JSON backup.

## Run locally

This is a dependency-free static web app. Open `index.html` in a modern browser, or serve the repository root with any static web server.

## Important current limitation

The first version uses browser local storage. Data remains in the current browser profile and does not sync to another device. Clearing the browser's site data can remove it, so export backups regularly.

There is not yet server-side authentication or a database connection. Do not enter full card numbers, CVVs, passwords, OTPs, or banking credentials. The app currently stores only the optional last four digits of a card.

## Oracle Cloud / PostgreSQL preparation

A starter PostgreSQL schema is in [database/schema.sql](database/schema.sql). It models cards and vouchers, including a per-voucher copy of purchased-from name and phone details.

The production stage still needs:
1. A PostgreSQL instance on Oracle Cloud.
2. A server-side API that connects to PostgreSQL (database credentials must stay on the server).
3. Real sign-in/session management and server-side ownership checks for every record.
4. A migration from local browser data to the authenticated account.
5. Deployment and testing with backups enabled.

The browser must never connect directly to PostgreSQL or contain database passwords.
