# RuPay Benefits

A private workspace for managing credit-card benefits and voucher inventory.

## Current storage: Firebase

The static frontend now connects to:
- Firebase Authentication using email/password.
- Cloud Firestore for each user's private workspace.
- Firestore path: `users/{uid}/workspace/main`.
- Firestore Security Rules that require authentication and match the signed-in user's UID.

No Oracle VM, Docker, Node server, or PostgreSQL deployment is required for the web app.

## Features

- Add credit cards with issuer, network, last four digits, benefit cycle, and benefit notes.
- Add voucher codes individually or in bulk (one code per line).
- Brand-wise inventory across Generated by me, Family cards, and Purchased from others.
- Search and filter by brand, origin, status, and supplier.
- Available, Sold, and Redeemed statuses.
- Supplier name and phone saved with purchased vouchers.
- Supplier history and upcoming expiries.
- JSON export/import backup.
- Email/password account sign-in and cross-device cloud sync.

## Firebase setup

Follow **[FIREBASE_SETUP.md](FIREBASE_SETUP.md)**.

1. Create a separate Firebase project.
2. Register a Firebase Web app and copy its public web configuration into `firebase-config.js`.
3. Enable Email/Password under Authentication.
4. Create a Firestore database.
5. Publish the supplied `firestore.rules`.
6. Deploy the static site over HTTPS.

The Firebase web configuration is public client configuration. Never commit service-account JSON files or private keys.

## Data migration

On the first sign-in in a browser, if the user's cloud workspace is empty, the app copies that browser's existing local cards and vouchers into the account. Existing local browser data is retained. Export a JSON backup before first sign-in as an additional precaution.

## Security and limits

- Firestore Rules restrict workspace access to the authenticated UID.
- Never store full card numbers, CVVs, OTPs, banking passwords, or payment credentials.
- Firestore has document-size and usage limits. This first cloud version stores the workspace in one document; keep voucher inventories modest and export backups regularly. A future scale-up can move records into per-record subcollections.
- Firebase free quotas are limited, not unlimited. Monitor usage and configure a Google Cloud budget alert.
- The legacy Express/PostgreSQL backend files remain in the repository for reference only; the static frontend does not call them.
